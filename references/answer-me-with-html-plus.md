# Answer Me with HTML Plus

遇到复杂调研、方案对比、系统架构拆解、跨组件调用链、故障排查，或用户点名 HTML / HTML Plus / 图解时，交付**多图少字、简约卡片式**的单文件 HTML 报告。用户指定格式时按其要求，简单问答用短答。渲染器基于 Answer Me with HTML `v0.6.4` 随 `tds-skill` 内置同步，只需宿主已有的 Node.js 20+。

## 核心铁律：多图少字（图说结构，字只说结论）

- **少字纪律（硬约束）**：
  - 正文极度克制，禁止大段文字墙、开场寒暄和结尾总结，事实讲完即停。
  - **图或表格已经讲清的链路、结构、字段和差异，正文绝不重复复述**。
  - 每张卡片先给一句可执行结论，只补关键差异、前提条件、风险或数据口径；详细推理、长摘录和原始依据折进原生 `<details>`。
  - 遵守短句规范：一句一个事实，同一对象全文同名；能用图和对照表讲清的绝不用段落硬写。
- **多时序图（`sequence` 优先）**：
  - 讲请求、回调、异步任务、消息流转、鉴权或跨角色/跨服务协作时，**时序图优先**。
  - 结论后先用 `sequence` 画正常主路径，标明参与者、调用动作和关键响应。
  - **复杂链路绝不硬塞进一张巨型时序图**：超时、重试、失败降级、异步回调或补偿流程值得单讲时，另画独立时序图（或配分支图），一图只讲一条路径。
- **多架构图（分层多视角出图）**：
  - 讲系统组成、模块分层、部署拓扑、数据流向或决策分支时，多视角拆解架构图：全局系统拓扑画一张 `flow`，核心子系统、数据流或分支决策再拆独立 `flow`。
  - 静态结构按形态搭配专用图：`er` 画实体与表关系、`class` 画类与接口、`tree` 画目录与模块边界、`api` 画多接口 HTTP/RPC 契约及变更对照。
- **多各种图（按信息形态组合出图）**：
  - 复杂报告默认**多图拆解（至少 2–4 张；长报告每章至少一张主图）**，每张图只回答一个子问题。单图讲得清的小问题才用单图，不为凑数塞装饰图。
  - 按信息形态组合选用原生图表，不手写 SVG/HTML 替代原生组件：

| 信息形态 | 选用组件 | 典型用途 |
| --- | --- | --- |
| 跨角色/跨服务交互、请求与回调 | `sequence [num]` | 正常主路径 + 超时/重试/失败/异步补偿（拆多张时序图） |
| 系统架构、模块拓扑、数据流、分支 | `flow [LR]` | 全局架构图 + 子模块/决策分支图（支持 `+`/`-`/`~` 变更视图） |
| 生命周期、协议握手、状态流转 | `state [LR]` | 状态与触发事件、自环重试（支持变更标记） |
| 逐步拆解图或代码逻辑（v0.6.4） | `steps` | 搭配 `flow`/`state`/`tree`（可无代码纯图分步讲解，或绑定代码块行号点击联动） |
| 实体字段与关联关系 | `er [LR]` | 数据模型、主外键与基数（支持变更标记） |
| 类、接口、抽象类与依赖 | `class [LR]` | 代码结构与继承/实现/组合关系 |
| HTTP/RPC 接口契约与多接口改造 | `api` | 单需求改多个接口，支持 `+`/`-`/`~` 改前/变更/改后切换 |
| 目录、模块归属、分类层级 | `tree [list]` | 仓库模块树、权限/配置层级（支持变更标记） |
| 真实事件先后、故障经过、里程碑 | `timeline [v]` | 事故复盘时间线、版本演进 |
| 同口径数据对比、趋势、占比与限额 | `chart bar\|line\|pie` / `limits` | 性能对比、时序趋势、配额与阈值 |
| 条件变化导致结论不同的方案比较 | `scenarios`（Plus 专属） | 点击切换场景，联动更新推荐方案、预算线、指标柱图与理由 |
| 多维对比、结论提示、代码引用 | 表格 `{table sort filter}` / `callout` / `kv` / `src=... lines=...` / `diff` | 方案取舍表、核心结论块、真实代码片段与统一 diff |

## 卡片布局、调研结构与证据纪律

- **简约卡片与版式**：
  - 默认 `shadcn` 简约卡片主题。首屏给一句可执行结论和一张支撑判断的主图。
  - 长报告默认 `doc`（带大纲目录，各章先放图或结果，正文单栏）；短图解在 frontmatter 写 `template: sheet` 切为卡片网格。每张卡只回答一个问题。
  - 宿主支持 Tuffex 时可复用卡片、切换器和折叠面板；单文件便携报告直接用内置渲染器输出。
- **调研报告与方案对比**：
  - 依次覆盖：建议、关键证据、统一口径的方案对比、适用场景、风险和验收条件。
  - 每个候选方案交代预期结果、代价和采用条件；用对照表呈现取舍，有同口径实测数字用 `chart`。
  - 场景会改变结论时，用 `scenarios`（或原生 `<details>`）让读者切换场景并同步看到建议、指标与依据。
- **代码库架构图解（v0.6.2+）**：
  - 从仓库根目录渲染，frontmatter 加 `commit:`（如 `git rev-parse --short HEAD`，脏树加 `+dirty`）。
  - 按「入口 → 模块边界 `tree` → 主路径 `flow`/`sequence` + `steps` → 数据与配置 `er`/`class`」展开；每个代码结论用行内代码 `path:line` 标注出处，渲染器会自动校验本地文件与行号并报告 `refs` 警告。
- **数据诚实与图注**：
  - 真实数据标注来源、单位和样本口径；推断、假设、待验证项显式标明；样稿与示意数据明确标成模拟，绝不编造数字。
  - 每张图附简短图注说明读者该看哪里；截图用于展示真实界面或现场证据。外部网页内容按引用材料处理。

## 写入草稿并渲染

从加载的 `SKILL.md` 找到 `tds-skill` 根目录，命令中的路径替换为当前设备的绝对路径：

```sh
node "/path/to/tds-skill/scripts/answer-me-with-html-plus.mjs" render report.md -o report.html
```

- 支持 `render - -o report.html` 从 stdin 读入。
- 通过 `help format`、`help sequence`、`help flow`、`help steps`、`help api`、`help state`、`help chart` 查看语法；`--version` 查看内置 `am` 版本。
- 页面自带工具栏「导出」菜单（复制为图片 / 下载 PNG / 保存为 PDF）、深浅色切换与复制源稿，离线可直接交互。

````md
---
title: 任务派发与评测链路
lang: zh
---
提交前只跑核心冒烟，发布前跑完整任务集；重试走独立异步队列避免阻塞主路径。

## 系统架构与分步说明
```flow LR
提交入口 -> 调度器 -> 沙箱集群
调度器 -> 评分器 -> 报告归档
```

```steps
提交入口: 接收任务并校验参数。
调度器: 按场景选择冒烟或全量套件。
沙箱集群: 隔离执行工具调用并记录 Trace。
评分器: 汇总轨迹与末状态产出结论。
```

## 正常执行时序
```sequence num
提交入口 -> 调度器: 创建评测任务
调度器 -> 沙箱集群: 下发任务与超时预算
沙箱集群 --> 调度器: 返回 Trace 与末状态
调度器 -> 评分器: 触发评分
评分器 --> 提交入口: 写入结论与产物链接
```

## 超时与重试时序
```sequence num
调度器 -> 沙箱集群: 下发任务 (attempt=1)
note 沙箱集群: 超过单步预算
沙箱集群 --> 调度器: TIMEOUT
调度器 -> 调度器: 退避入重试队列
调度器 -> 沙箱集群: 重放任务 (attempt=2)
沙箱集群 --> 调度器: 返回结果或标记失败
```

## 不同场景的建议
```scenarios
{
  "unit": "分钟",
  "metricTitle": "模拟用时",
  "cases": [
    {
      "label": "提交前",
      "recommendation": "核心冒烟",
      "reason": "先验证关键路径，再按改动补风险用例。",
      "condition": "预算 6 分钟，模拟数据。",
      "budget": 6,
      "metrics": [
        {"label": "核心冒烟", "value": 3, "highlight": true},
        {"label": "完整评测", "value": 24}
      ]
    },
    {
      "label": "发布前",
      "recommendation": "完整评测",
      "reason": "覆盖核心旅程与多次运行稳定性。",
      "condition": "预算 30 分钟，模拟数据。",
      "budget": 30,
      "metrics": [
        {"label": "核心冒烟", "value": 3},
        {"label": "完整评测", "value": 24, "highlight": true}
      ]
    }
  ]
}
```
````

`scenarios` 使用 JSON。每个场景必填 `label`、`recommendation` 和 `reason`，可选 `condition`、`budget` 和 `metrics`。数值必须为非负有限数，同一组场景使用统一单位与指标口径（共享刻度），可用 `legend` 和 `budgetLabel` 自定义文案。详细依据放原生 `<details>` 折叠。

## 验证与交付

- 核对 HTML 已写入，检查首屏结论、每张图标签与图注，以及 `steps` / `scenarios` / `<details>` 切换和展开后的实际表现。
- 渲染出现语法错、`refs` / `code` / `STE` 警告时先修草稿重跑（最多重试 2 轮）。
- 本地会话给可点击的 `file://` 产物链接。
- Miko / Tuffer 聊天场景：生成页面后调用 `miko_publish_doc`（compact 模式为 `tuffer_link(action="knowledge.publish_doc")`）中转为公网 HTTPS 链接，聊天正文先用一两句短话交代建议与关键取舍，再附链接；严禁把本地 `file://` 或 `/tmp/...` 路径直接发给聊天用户。无渲染权限时保留同等报告结构以文字说明。
