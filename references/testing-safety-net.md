# 测试覆盖与密封闭环规范

## 适用范围

编写或补充测试用例、修复 Bug 补回归、为重构老代码搭建保护网、治理不稳定测试，或评估属性测试（PBT）、变异测试与确定性仿真（DST）选型时，读取并遵循本规范。

本规范追求两件事：用**高信噪比用例覆盖关键业务承诺**，用**密封闭环测试把验证时间压到秒级到分钟级且 100% 可复现**，让人工和 AI 都敢放心改代码。

## 1. 统一抽象：所有测试只管四件事

不要被 L0～L4、黄金快照、PBT、变异测试、确定性仿真等名词拆散注意力。所有测试手段都在同时解决四个正交问题：

| 抽象轴 | 低阶形态（易漏/难复现） | 高阶形态（机器化/可复现） | 解决的核心问题 |
| --- | --- | --- | --- |
| **出题空间（喂什么）** | 手写少量正例、手工点屏 | 历史快照重放（Golden Master）→ 随机数据生成（PBT）→ 随机时序交错（DST） | 突破人脑与 AI 的输入和时序盲区 |
| **裁判标准（怎么判）** | 人工肉眼核对、`res != null` 空断言 | 强类型与单源契约（L0）→ 明确业务规则（L1）→ 新旧差分与业务阈值（L3）→ 守恒定律（L4）+ 变异验裁判 | 明确“什么算对”，防止假测试放行 |
| **考场稳度（稳不稳）** | 连共享测试库、抢真机、`sleep` 硬等 | 纯内存密封（L1）→ 独占临时依赖与本地 Mock（L2）→ 虚拟时钟与固定种子（DST） | 拔掉外部不确定性，消灭闪烁和环境争抢 |
| **权力边界（谁改卷）** | 同一个 Agent 边改实现边改测试 | 编码与出卷分权、关键测试只读、执行总数核对 | 防止 AI 弱化断言或伪造绿灯 |

## 2. 有效测试用例覆盖

覆盖率只说明代码被执行过，不说明输出经过正确检验。衡量一套用例值不值，只看它能否在业务承诺被破坏时稳定报红。

### 2.1 用例准入与四象限靶点

每条新用例必须能答清三件事：**保护哪条业务或用户规则、失败时该采取什么动作、比已有用例多抓了哪类错误**。答不上来的不写。

为核心逻辑铺开用例时，覆盖四个象限，拒绝只测顺风路径：

1. **正常典型值（Happy Path）**：最常见的主路径输入与完整输出校验。
2. **零值与极端边界**：空串、空集合、`0`、负数、超长输入、缺失字段。
3. **临界跳变点（Off-by-one 杀手）**：凡有阈值（如 `>= 500`、`<= 32`），必测 `n-1`、`n`、`n+1` 三个紧邻点，专杀 `>` 与 `>=` 写反。
4. **显式异常与权限拒绝**：空身份、越权角色、非法外部 URL、超限体积、上游超时或 `4xx`/`5xx`，断言返回预期错误码而非静默放行或崩溃。

### 2.2 故障棘轮与防用例膨胀

修 Bug 与加用例必须兼顾防复发和控制体积，避免 AI 堆出大量无人维护的冗余基线：

- **先见红再见绿**：凡能自动复现的 Bug，先写出在旧代码上稳定失败的测试，再改实现使之通过。
- **优先合并补强，不机械新增**：已有同类规则测试时，优先往原测试组里补边界输入或强断言，不按“每个 Bug 一个新文件”无限累加。
- **同题降层**：最初靠整机或长样本发现的缺陷，一旦查清根因可用纯内存固定输入稳定复现，就把日常回归下沉到快测试层；大样本只保留给确实覆盖端到端组装风险的场景。
- **克制举一反三**：修完一个缺陷时，只做两项扩展：排查同仓库同类阈值或入口是否同错、补齐同一规则边界的另一侧；禁止让 AI 穷举跑同一条代码分支的排列组合。
- **定期修剪**：规则退役，或已有更小、更稳的用例覆盖同一错误机制时，删掉旧的重复用例。

### 2.3 防 AI 假测试的轻量验真

不要把全仓库“80% 变异分数”当成一刀切 KPI（运行慢，且约四分之一以上真实故障变异体模拟不了），改用两种低成本验真法：

- **增量变异抽检**：仅对核心规则模块本次 PR 改动的 Diff 跑增量变异（如 `cargo-mutants --in-diff`、`Stryker --incremental`、`gremlins`、`mutmut`），控制在 1 分钟内；存活变异体直接暴露无牙断言。
- **零工具投毒证红**：未接入变异工具时，对高危逻辑（鉴权、计费、熔断、阈值判档）手工或临时改坏一行关键条件（如删掉权限校验、把 `>=` 改为 `>`），确认目标测试立即失败后再还原，防止写出永远为真的空断言。

## 3. 密封闭环测试（Hermetic Closed-Loop）

### 3.1 硬定义

- **密封（Hermetic）**：换一台机器、拔掉外网、打乱执行顺序、并发跑多份，测试结果依然 100% 由测试自身决定，不受外部世界波动干扰。
- **闭环（Closed-Loop）**：从**公开入口进入 → 经过真实核心业务与契约校验 → 核对最终可观察状态或输出**，让开发与 AI 在改完代码后几秒到几分钟内就能拿到可信放行结论，不攒到联调或真机点屏才排雷。

### 3.2 剥离四大外部熵源

导致测试慢、乱闪或依赖共享环境的根源只有四个全局变量：**系统真实时钟、随机数生成器、外部网络与硬件 I/O、共享持久状态**。

遇到 I/O 与外部依赖时，先区分测试目标再选隔离方式：

| 测试目标 | 密封闭环做法 | 典型约束 |
| --- | --- | --- |
| **验证业务规则**（含超时、重试、冷却、状态流转） | 采用“纯逻辑内核 + 薄 I/O 外壳”，把时钟和 I/O 移到边界接口，用可控内存替身和**虚拟时钟（FakeClock）**瞬间推进退避与过期 | 单进程纯内存运行、毫秒级完成、允许高并发无锁乱序执行 |
| **验证 I/O 与存储语义**（SQL 事务、唯一约束、文件原子写、编解码） | 使用**每次独占的真实依赖**：仓库内固定小样本、独立 `tempdir()`、端口 `0` 动态分配、临时真实容器库（Testcontainers）并按用例隔离数据 | 测完自动销毁清零；严禁连共享测试服、写死 `/tmp/fixed` 或固定端口 |
| **验证跨模块与外部接缝**（前后端、微服务、软硬件 HAL） | 同仓用**单一契约源码生成**（OpenAPI / Protobuf / Schema）把字段和枚举错位前移到编译期；跨仓用**本地可故障注入 Mock 替身**加录制回放标本库跑通全异常闭环 | 外部真实服务与真机台架只留给发版前低频冒烟及线上探针，不绑死日常 PR |

### 3.3 防闪烁与环境安全铁律

一旦测试网出现假红灯，团队会迅速养成重跑绕过的习惯，整张网失去公信力。必须死守以下红线：

1. **封禁硬等待**：严禁在测试中写 `sleep`、`setTimeout`、`waitForTimeout` 等固定时长等待；统一改用状态就绪信号、有界条件轮询或虚拟时钟。
2. **主干禁无脑重试**：主干阻断门禁默认 `retry = 0`；禁止用自动重试把真实并发竞态扫进地毯底下。
3. **新测试乱序拷机**：新增或改动的并发、异步与状态机测试，提交前在本地或 CI 做多轮乱序压跑（如 `go test -shuffle=on -count=100`、`cargo nextest --stress-count 100`、`pytest --random-order --count=100`）。
4. **闪烁隔离检疫**：同一 Commit 上出现“一红一绿”的测试，立即移出主干阻断线进入检疫清单并限期查清根因（区分测试未隔离还是业务真实竞态），超期未修直接重写或清除。
5. **环境目标强断言**：任何测试或预发部署脚本必须校验目标主机与环境白名单，严禁出现名为 `stage` / `test` 的配置或作业实际指向生产环境；严禁在群聊或日志明文传递测试令牌。

## 4. 五层分级与深水技术精准分流

不要在所有仓库平均铺开五层，更不要给常规业务硬上重型仿真。按模块病理分类配药：

| 模块类型 | 必须守住的核心防线 | 深水技术（PBT / 变异 / DST）有效应对策略 | 严禁硬上的浪费项 |
| --- | --- | --- | --- |
| **业务联调与 CRUD / 前端界面** | **L0** 单源契约与强类型 + **L1** 核心表单/权限规则单测 + **L2** 本地 Mock / 临时容器 + 少量核心主路径 E2E（≤ 5% 占比） | 常规模块不强推 PBT 与 DST；高危权限或计费接口按 Diff 做增量变异或投毒证红 | 严禁全仓铺 E2E 倒金字塔；严禁为增删改查硬写属性生成器或虚拟网络仿真 |
| **算法、音视频与解析引擎** | **L1** 密封小测试 + **L3 黄金快照（Golden Master）**（固定代表样本新旧对拍 + 业务签字差异阈值） | **优先用轻 PBT**：直接挂进现有单测框架写 3～5 条守恒定律（往返律、有界律、幂等律、新旧考官对照律）；PR 跑 200 组，夜间跑万组，反例自动缩减后冻结成普通单测 | 严禁无多样本对拍直接全量切流；严禁用纯技术主观拍板替代业务差异阈值 |
| **调度、同步与并发状态机** | **L1** 边界与权限单测 + 异步超时/熔断/幂等闭环测试 + 线上自探针（Probers） | **DST 三档降级**：① 轻档：时钟与网络接口化，用虚拟时钟 10 ms 跑完分钟级超时与冷却；② 中档：把状态机抽成纯函数，用固定 `seed` 随机打乱事件顺序跑 1,000 步查安全/活性铁律，报错记 `seed` 秒级复现；③ 重档全系统虚拟 OS/网络仿真仅用于分布式存储或强一致核心引擎，其余明确延后 | 严禁在未接口化 I/O 的老系统里硬造全系统重型仿真平台 |

老系统改造遵循增量止血路线：不搞停工全员补测试；先立“新功能与修 Bug 必带回归”红线，再给热点高危模块外圈罩上黄金快照、在外部依赖处切开接缝换上本地替身，最后按事故高频区逐块替换重构。

## 5. AI 协作分权与诚实验证

- **出卷与答卷分离**：处于功能开发、Bug 修复或重构模式时，严禁私自弱化断言、注释失败用例、针对测试输入写硬编码特判，或提前 `exit(0)` 逃避检查。
- **改预期先确认**：只有确认业务规格变化、旧测试本身断言错误或测试夹具存在非密封缺陷时，才能修改测试代码，且必须显式说明改了哪条预期和依据。
- **诚实标明验证层级**：汇报验证结果时，必须严格区分以下四类证据，不互相冒充：
  - **静态与编译通过**：只证明类型与语法有效。
  - **密封单测 / 契约替身通过**：证明纯逻辑与约定接口在隔离环境下成立，不等价于外部真实联调通过。
  - **真实端到端 / 真机验证通过**：证明真实组装与运行路径成立，仍需写明未覆盖的硬件或环境限制。
  - **生产自探针与监控正常**：证明线上持续可用。
- **禁止假绿灯**：跳过测试、工具未注册、远端访问被拒、凭“重启可恢复”绕过的异常，一律不得标为通过。

## 6. 完成检查表

- [ ] 新功能或缺陷修复已覆盖正常值、空/极端边界、临界跳变与异常拒绝四象限。
- [ ] Bug 修复已在旧实现上复现失败，且优先合并补强同类用例而非制造冗余。
- [ ] 核心逻辑测试完全密封：断网可跑、无硬编码 `sleep`、无共享固定端口或固定临时路径。
- [ ] 涉及跨端或跨服务字段变更时，已用单源契约或本地替身验证，未靠口头对账放行。
- [ ] 算法或老模块改造已保留代表性黄金样本对拍，并与业务确认差异放行阈值。
- [ ] 未静默删改或弱化已有测试断言；验证报告如实区分密封测试、替身联调与真实端到端结果。
- [ ] 测试与预发部署目标已核验，确认未误指生产环境，未暴露明文凭据。

## 反模式

- 只盯行覆盖率数字，放任 AI 批量生成 `assert result != null` 的空洞测试。
- 遇到异步失败直接加 `sleep(2000)` 或给主干流水线加 `retries: 3` 掩盖真竞态。
- 每个线上 Bug 都机械堆独立大文件，从不合并、降层或修剪失效用例。
- 把测试全压在手工真机点测和跨群口头催联调，形成“L2/L3 臃肿、L0/L1 空白”的倒金字塔。
- 不看模块类型，在普通 CRUD 或前端业务里强推全仓变异指标或重型确定性仿真。
- 用单条样本通过、本地 Mock 绿灯或“重启后恢复”代替真实场景的回归验收。
- 让编码 Agent 在同一轮里既改业务实现又悄悄放宽失败测试断言以凑齐绿灯。
